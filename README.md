# 02_filtering: Preparing reads for genome assembly by trimming and filtering

We have established the quality of the raw data. Next, the reads must be filtered. They have already had the adapters trimmed by default, so no adapter trimming tools such as Porechop_ABI are required. The reads will be filtered by thresholding quality score and read length using Chopper (trims out those which don't pass the filters). Once this process has been conducted with parameters/thresholds determined suitable for the MM genome, the reads will be much better quality and well-prepared for genome assembly.

## Filtering reads with Chopper

Chopper is a versatile tool which can filter based on average read quality, min/max read lengths and GC content. It then trims by a chosen method (see more info here https://github.com/wdecoster/chopper), in this case I used a Q15 (95% accuracy) quality score threshold and a >20Kb read length cutoff.

Performing filtering and quality-based trimming using Chopper:

```
bash /02_filtering/scripts/run_chopper.sh
```

After trial and error, I found that the best tradeoff between coverage (aiming for at least 30x coverage per haplotype) and quality/length was using thresholds for Q13 (~95% accuracy) and 15Kb read lengths. The coverage can be seen in the 'Filtered ONT read quality summary' further down.

# 03_assembly: Assembling filtered reads with Hifiasm, model selection to choose an assembly

The set up is all done and now it is time to actually run some assemblies. Hifiasm is a haplotype-resolved de novo genome assembler, which is very appropriate for our hybrid species *Eucalyptus x phylacis* (Meelup Mallee) genome because the goal is to assemble the contigs into chromosome sets of each parent.

Assembling the filtered reads using Hifiasm:

```
bash /03_assembly/scripts/run_hifiasm.sh
```
Important note: On the first run, Hifiasm was confused by the heterozygous peak being larger (see genomescope discussion) and tried to set that as the homozygous peak, failing to set a heterozygous peak at all. The peak number Hifiasm uses will not be the same as the visible coverage peak on the GenomeScope profile (36x).
To fix the issue, I identified the "peak_hom" value of the first assembly (28), then doubled it (56) so Hifiasm recognises the second peak as the homozygous peak and can identify the large peak as the heterozygous one as intended. This has been updated and fixed in the script above.


The reads have now been assembled, and a range of analysis with tools can be conducted to evaluate the assembly before coding for parental assignment.

## Genome Completeness - BUSCO

Benchmarking Universal Single-Copy Orthologs (BUSCO) is a crucial step in genome assembly used for measuring assembly quality. It measures genome completeness as a percentage by searching the genome for a predetermined set of single-copy genes. In this project I downloaded the recent OrthoDB v12 catalog which has been used for Ash's *Spinifex sericeus* assembly, but using the eudicots `odb_eudicotyledons12` (*S. sericius* is a monocot).

Compleasm is an efficient tool to measure genome completeness, which I have used in the following script. This provides BUSCO genome completeness metrics for the primary and haplotype assemblies from the improved Hifiasm runthrough.

```
bash 03_assembly/scripts/compleasm_busco.sh
```

The same metrics will be computed after parental assignment, when the current haplotype assemblies which are a patchwork of contigs from both parents will be arranged into two parental haplotypes. If the metrics remain at a similar level or improve, this genome is likely worthy of publication.

# 04_parental_assignment: Alignments against parent genomes for haplotype-resolved assembly

In order to move from the phased assembly made with Hifiasm to sets of contigs that can be conifdently assigned by parent (*E. decipiens*, *E. virginea*), knowledge of common sequences in the parent genomes is required to assess likelihood of each contig being from a given parent. Thankfully, NCBI datasets have publicly available assemblies for *E. decipiens* and *E. virginea* which can be downloaded for use in this project with the following script:

```
bash 04_parental_assignment/scripts/get_parents.sh
```

The approach I chose to perform parental assignment was to align Haplotype 1 and Haplotype 2 assemblies each against **both** parent genomes. Then by analysing the alignment scores of every contig within them, most/all contigs should clearly be better aligned to one parent. Grouping *E. decipiens* contigs and *E. virginea* contigs will then be a solid representation of the true parental haplotype genomes for *E. phylacis*. The alignments are performed with this script, again using minimap2 with a similar method to the earlier Haplotype 1 vs Haplotype 2 alignment:

```
bash 04_parental_assignment/scripts/align_parents.sh
```

Now each contig in the haplotype assemblies has been mapped to a best-matching chromosome from decipiens and virginea. To assess the alignments and make conclusions on parental origin of each haplotig, I made the following scripts to produce tables comparing coverage percentage and identity percentage of alignments to each parent. Better coverage in alignment to one parent species chromosome and large gap in identity percentages between alignments to each parent are strong signs that the contig belongs to a specific parent.

## Filtering Assembly Contigs

In this step, I had to make informed choices on the thresholds used to filter out contigs based on my available information. The BlobPlot combined with the final table were crucial for doing this. I chose to remove all non-streptophyta labelled contigs, **except** for the two large Artverviricota contigs (one in each haplotype assembly) which are mislabelled due to summation of viral hits outweighing the top streptophyta hit. Then I chose to filter out all contigs under 1 Mbp in length, as this seemed appropriate given the final table (around 35 contigs over this limit) and the estimated genome size of ~500-600Mbp (under 1Mbp is probably not going to represent a chromosome or large chromosomal arm). Lastly I also filtered by coverage, using the 28x heterozygous peak coverage per haplotype from assembly and the BlobPlot distribution of coverage as a guide. I ruled out any contigs with coverage under 20x (much lower than target coverage, probably not useful) or over 90x (~3x target coverage peak, even contigs from homozygous peak area that show up in both parents shouldn't get this high).

## Parental Assignment for Selected Contigs

The final step of assigning contigs as being from *E. decipiens*, *E. virginea* or ambiguous was run for the refined set of contigs left after the filtering above. These represent either full chromosomes inherited from the parents or chromosomal arms, which may represent remaining chromosomes in a few pieces. As such, getting clear assignment of these means that most/all chromosome locations in the *E. phylacis* genome can be known to come from one parent or the other.

bash 04_parental_assignment/scripts/parent_contig_binning.sh \
    04_parental_assignment/results/filtered_hap1.fa \
    04_parental_assignment/results/hap1_vs_decipiens.paf \
